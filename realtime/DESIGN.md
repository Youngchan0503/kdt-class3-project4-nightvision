# 설계 (0단계)

> 결정일: 2026-11-08

## 무엇을 만드는가

| 항목 | 결정 |
|---|---|
| 목적 | 실사용 앱이 아니라 **시연용** |
| 화면 | **PC 화면만** |
| 입력 | **사진 업로드 / 영상 업로드 / 실시간 카메라** 3가지 |
| 오버레이 내용 | 미정 — 모델이 실제로 무엇을 잡는지 본 뒤 결정 |
| 경고 방식 | 미정 |

## 코드 구조 원칙

1. **메인 파일은 `stair_vision.py` 하나.** 분석 로직은 항상 여기서만 고친다.
   백엔드/프론트는 이 파일을 `import`해서 쓰기만 한다.
2. **입력이 3가지여도 분석 함수는 하나.** 사진·영상·카메라는 모두 "프레임"이다.

   ```
   사진 ─┐
   영상 ─┼─▶ 프레임 ─▶ analyze() ─▶ result ─▶ draw() ─▶ 화면
   카메라 ┘
   ```
3. **분석(`analyze`)과 그리기(`draw`)를 분리.** `analyze()`는 데이터(dict)만 반환한다.
   오버레이를 바꿔도 분석 코드는 건드리지 않는다.
4. **`result`는 최소한으로 시작**하고, 필요해질 때 항목을 추가한다.
5. **화면은 원본 그대로, 탐지 결과만 덧그린다.** (2026-11-08 결정)
   전처리는 모델 입력에만 쓴다. 전처리한 화면을 보여주면 처리 시간만큼 화면이 늦게 따라와
   실제 움직임과 어긋나고 멀미를 유발할 수 있다. 전처리는 밝기만 바꾸고 좌표는 그대로라
   탐지 결과를 원본 위에 그대로 그릴 수 있다. (`draw(on_model_input=True)`는 디버깅용)
6. **학습 코드는 별도 파일(`train.py`).** 메인 파일은 "학습된 모델을 쓰는 쪽"이다.
7. **설정값은 파일 맨 위 / 실행 인자로.** 값만 바꿔서 예전 단계를 재현할 수 있게 한다.

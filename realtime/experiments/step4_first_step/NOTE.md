# 4단계: 직접 라벨링한 첫 단차 데이터로 학습

- 날짜: 2026-11-08
- 목적: 계단 전체가 아니라 발 앞 첫 단차 하나를 찾는 모델 만들기
- 데이터: `dataset_custom_stairs` (`realtime/datasets/first_step.yaml`)
  - 123장 (train 97 / val 26), 발 앞 첫 디딤판을 4점 폴리곤으로 라벨링
  - 클래스: `ascending_stairs`(오르막) 객체 train 74 / val 20, `descending_stairs`(내리막) train 9 / val 2
- 시작 가중치: `step2_stairs_v3/weights/best.pt` (공개 계단 데이터로 학습한 모델 → 계단을 아는 상태에서 첫 단차를 학습)
- 설정: epochs 100, imgsz 640, batch 16, seed 0, cache ram, 그 외 ultralytics 기본값 (학습 이미지는 전처리 없이 원본)
- 실행: `realtime/train.py --data realtime/datasets/first_step.yaml --name step4_first_step --model realtime/experiments/step2_stairs_v3/weights/best.pt --epochs 100 --cache --no-test`

## 결과 3: 실시간이라고 치고 시뮬레이션 (`make_realtime_demo.py`)

모델은 한 번에 한 프레임만 분석하고(바쁜 동안 들어온 프레임은 건너뜀), 화면은 원본을 바로 보여주며

| 방식 | 처리 시간 평균 (p95) | 분석한 프레임 | 화면 결과의 지연 평균 (최대) | 탐지 표시 프레임 |

## 해석

- **찾을 때는 첫 단차만 정확히 잡는다.** 계단 전체 모델처럼 평평한 바닥이나 벽을 칠하지 않는다 (500, 800, 900번 프레임)
- **이 모델에는 전처리가 오히려 방해.** 라벨링 사진을 원본 그대로 학습했기 때문에, 밝힌 이미지를 넣으면 학습 때와 다른 입력이 된다 (14% vs 46%).
  공개 데이터 모델은 전처리로 좋아졌던 것과 반대 → 모델마다 학습 때와 같은 입력을 넣어야 한다
- 기준 0.10으로 낮추면 더 많이 잡지만 벽을 잡기 시작함 (500번) → 0.25 유지
- **남은 한계**
  - 계단이 보이는데 놓치는 프레임이 많음 (탐지 46%)
  - 프레임마다 흔들림 (전환 153번) — 찾는 프레임과 못 찾는 프레임이 번갈아 나옴
  - 오르막 영상인데 일부를 내리막으로 분류 (73프레임) — 내리막 학습 데이터 9개로 부족
- 다음 개선 후보: 내리막 데이터 추가, 어두운 사진에 전처리를 적용한 이미지로 학습해 입력을 맞추기, 프레임 간 결과를 이어 주는 추적(흔들림 완화)
